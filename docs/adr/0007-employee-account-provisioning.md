# 员工档案与系统账号：档案单向持有账号，建档即开号并授默认角色

员工档案（`hrm_employee`）与后台账号（`manage_user`）此前只有一条半通的小路：`hrm_employee.user_uuid` 单列指针存在，但只有工具栏的批量「生成用户」会填它，新增/导入/入职单审批建档都不建号，生成出来的账号不挂任何角色（登录即零菜单），删除两侧各留垃圾，离职员工账号照常能登录。决定：**账号是员工档案的投影**——档案是唯一写入方，建档（含导入、入职单审批自动建档）在同一事务内自动开号并授默认角色 `R_EMPLOYEE`；账号侧不反向写档案，只读展示关联员工。

实现契约：

- **指针与基数**：沿用 `hrm_employee.user_uuid` 单列（空串=未关联），不加 `manage_user` 侧反向列，不改 NULL 语义、不加库级唯一索引。一对一在应用层校验：关联时若目标账号已被其他档案持有，报错拒绝。
- **自动开号**：`addEmployee`、`importEmployee`、`entry/archive.go`（入职单审批通过自动建档）三个入口统一开号；`person_status='5'`（离职，补录历史员工）跳过开号。开号字段沿用既有约定：`username=employee_no`、`password=hrm.initialUserPassword`（兜底 `123456`）、`status='1'`、昵称/性别/手机/邮箱取自档案。批量「生成用户」按钮保留，降级为存量档案的修复工具。
- **默认角色**：种子 `R_EMPLOYEE`（普通员工），`manage_role_menu` 只授自服务页：首页、个人中心、考勤打卡、个人看板、我的培训、目标确认、自评填报、结果确认。「评审填报」「考核任务工作台」属管理者视角，不授（其可见范围取决于下属树数据权限，未经校验）。角色码写进配置 `hrm.defaultRoleCode`（默认 `R_EMPLOYEE`）：角色不存在时只建号不挂角色并打 warn，开通流程不因配置缺失而失败。
- **用户名与工号解耦**：`username` 仅在开号时取工号，此后工号变更不重命名账号（登录凭证不得在背后漂移，且改名有撞 `uni_manage_user_username` 的风险）。员工列表加「登录账号」列暴露二者可能不一致。
- **关联与解绑**：唯一写入入口在员工侧——编辑弹窗「系统账号」区块，支持远程搜索候选账号（排除已被占用的）、新建并关联、解除关联。解绑保留账号。用户管理侧只加只读「关联员工」列（工号+姓名），不做写入。
- **生命周期一致性**：删档案级联删账号**及其 `manage_user_role` 行**；删除被档案引用的账号**拒绝**（提示先解绑）；离职（`person_status='5'`）自动置账号 `status='2'`（禁用）；登录处校验 `status != '2'`，禁用账号不可登录。
- **`status` 真值**：`'1' 启用 / '2' 禁用`，与 `Api.Common.EnableStatus`、`enableStatusRecord`、`enableStatusOptions` 及库内现有一致。`Api.Manage.EnableStatus = '0' | '1'` 是注释（"2": Disable）与联合类型自相矛盾的孤立笔误，仅被 `AddUserRequest`/`EditUserRequest` 引用，改为引用 `Api.Common.EnableStatus`。
- **初始密码**：新增成功后的响应回带用户名与初始密码，前端弹窗明示。自助改密（旧密码+新密码）不在本主题内，记为后续项。

Considered Options: 双向同步（账号变更写回档案）——两侧同时可写必然产生冲突语义，且现状连事务都没有，故选档案单写；`manage_user` 加 `employee_uuid` 反向列——一对一只需一个指针，反向列会引入两个真相源；按岗位/职务推导角色——映射关系在仓库中不存在，等于凭空造一套权限模型；不授角色只建号——登录即白屏，等于没打通；删除账号只解绑——留下大量无主账号；`status` 改用新列 `disabled`——会造出两个都表示"能否登录"的列。

Consequences: 员工档案的新增/导入/审批建档路径都多一次 `manage_user` + `manage_user_role` 写入，全部包在原事务内，任一失败整体回滚（导入不再能"部分成功跳过开号失败的行"）。存量数据由迁移补挂：给"零角色且已关联档案"的账号补 `R_EMPLOYEE`；无账号的存量档案不自动建号（避免迁移静默产出 `123456` 账号），走批量「生成用户」。`pwd_login.go` 新增 status 校验会改变既有语义：库里已存在的禁用账号从此真的登不进去。
