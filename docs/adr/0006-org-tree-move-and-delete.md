# 组织树：编辑可移动节点（环检测），删除保持自底向上

组织管理（`/hrm/org/orginfo`）最初编辑不可换父、删除有子节点即报错，被反馈"平级管理、不符合真实树形结构"。决定：**编辑支持移动节点**（`editOrg` 接受可选 `parentUuid`，换父时后端沿目标父向上遍历做环检测，把自己挂到自己或子孙下返回 10325 `OrgMoveCycleCode`），**删除保持"存在下级组织则拒绝"不级联**。

实现契约：

- 前端编辑弹窗父组织用 `NTreeSelect`（数据源 `GetOrgTree`），选项构建时排除编辑节点自身及其整个子树（前端先挡一道，后端环检测兜底）；清空即升为根组织。
- `parentUuid` 为 optional：空或不变化时不更新 `parent_uuid` 字段，存量调用方（导入、e2e）不受影响。
- 删除仍走 `DeleteRequest{uuids[]}` 批量接口，单条删除即 `DeleteOrg([uuid])`；有子节点报 `OrgHasChildrenCode`，不做级联——组织下挂员工/考勤/薪酬等引用，级联误删整棵子树代价过高。
- 新错误码：`OrgMoveCycleCode = 10325`。

Considered Options: 级联删除组织（一键删整棵子树，但组织是员工/考勤组/薪酬主体的外键锚点，静默级联风险大于便利）；移动节点仅前端校验（后端不做环检测——并发下前端快照过期会写出自成环的树，后端遍历父链是唯一可信闸口）；改用闭包表/物化路径存层级（现规模全表内存组树足够，`parent_uuid` 单列改动最小）。

Consequences: 编辑弹窗多一次 `GetOrgTree` 请求（仅在编辑模式）。环检测是 O(树高) 的逐行查询，组织树很深时可用一次全表加载替代。页面操作列不参与列设置过滤（`operate` 列豁免 `columnChecks`），权限码大小写以数据库下发为准（`hrm:org:addChild` 驼峰）。
